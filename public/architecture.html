System Overview
Daromadchi is a multi-marketplace seller dashboard for Uzbekistan. It syncs orders, inventory, and stock across Uzum Market and Yandex Market. Web dashboard + Chrome Extension for seller analytics. Marketplace integrations are read-only by default — the one exception is the opt-in, per-shop stock-sync mode, which writes only the stock quantity through a single audited writer after the seller consents.

ATMOS Payment Integration
ATMOS is the Uzbek payment aggregator that handles all subscription charges. Money is integer tiyin (1 so'm = 100 tiyin). Two card-binding flows: UzCard/Humo (direct in-app binding with SMS OTP) and Visa/Mastercard (hosted binding via MPS). Amount is ALWAYS derived server-side from PLAN_PRICES_TIYIN — never trusted from the client. ATMOS has no native recurring billing, so auto-renewal is a custom cron that charges stored card tokens.
OAuth2 Token
client_credentials grant. Token cached in-memory with proactive refresh (5min before expiry). Automatic 401 retry with fresh token.
ATMOS_CONSUMER_KEYATMOS_CONSUMER_SECRET
UzCard / Humo Path
Direct card binding. PAN entered in-app (transit-only, never stored). SMS OTP confirms binding. Returns reusable card_token. Charge: payCreate → payPreApply → payApply (literal OTP "111111").
Visa / MC Path
Hosted card-bind page on ATMOS domain. PAN never touches our server. Returns card_id via callback. Charge: mpsPreCreate → mpsCreateBind. May require 3DS redirect.
10 environment variables configure the ATMOS integration: ATMOS_BASE_URL, ATMOS_STORE_ID, ATMOS_CONSUMER_KEY, ATMOS_CONSUMER_SECRET, ATMOS_CALLBACK_URL, ATMOS_CALLBACK_API_KEY, ATMOS_CALLBACK_CIDR (optional IP allowlist), ATMOS_HOSTED_BIND_RETURN_URL, ATMOS_HOSTED_BIND_CALLBACK_URL, BILLING_AUTORENEW_ENABLED.

Activation Logic (Exactly-Once)
applyAtmosPaymentSuccess() in lib/billing/activate.ts is THE ONE PLACE where payment → SUCCESS and subscription → active happens. Every payment flow converges here.
Exactly-Once Guard
Conditional UPDATE gated on atmos_status NOT IN ('SUCCESS','FAILED'). If the row is already final, the UPDATE matches 0 rows and returns early. DB row lock serializes concurrent callers (callback + cron arriving simultaneously).
What It Does
1. Sets payment atmos_status = 'SUCCESS'
2. Sets subscription status = 'active'
3. Extends period: MAX(now, current_expiry) + plan months
4. Sets users.plan to the plan key
5. COALESCE on agreed_amount_tiyin (self-heals, never overwrites existing)
Period extension uses addMonths with day-clamping: A plan bought on Jan 31 expires Feb 28, not Mar 3. The old setMonth() silently rolled overflow forward, making every month-end purchase run long.
isPlanKey() gating: Every plan checkout can sell must be grantable via isPlanKey(). This check prevented Biznes from being charged but never activated — the plan was added to PLAN_PRICES_TIYIN but checkout was blocked.

Cancellation & Resume
cancelPlan(userId)
lib/billing/cancel.ts
Does: Sets ALL live subscriptions to status='cancelled', autorenew=false. Computes access_until = current_period_end. Records cancellation state.

Does NOT: Touch users.plan. Touch plan_expires_at. Remove card token. Refund anything. Immediately lock the seller out.

The seller keeps full access until the period they already paid for expires.
resumePlan(userId)
lib/billing/cancel.ts
Does: Sets subscription back to status='active', autorenew=true. Only works while access_until > now (period still active).

Does NOT: Charge anything. Extend the period. Change the plan.

If period is over, returns 'period_over' — seller needs a fresh checkout.

Trial System
New accounts get a 14-day free trial (TRIAL_DAYS = 14). Trial grants access to TRIAL_FEATURES (all paid features). Trial is computed from trial_ends_at — no status column needed.
Trial Start
trial_ends_at is set on account creation: now + 14 days. No action needed to start the trial — it's automatic for every new signup.
Trial End
When trial_ends_at < now AND users.plan = 'free', paid features are locked. Nudge notifications fire: trial_ending (before) and trial_ended (after).
Nudge Notifications
Suggestions only — nothing here changes a plan, an entitlement, or a price. Runs daily via expire-plans job. Throttled via user_notices unique (user_id, kind) — the upsert IS the throttle.

Stock Sync & Write System
The ONE sanctioned write exception to the read-only marketplace rule. pushStock() in lib/marketplace/stock-writer.ts is the single module that writes to marketplace APIs. Only updates stock quantity (ostatok), only after the seller opts in, and every write is fully audited.
pushStock() Safety Layers
8 layers of defense — any failure aborts the write
#GuardWhat it checks
1Kill switchSTOCK_WRITE_ENABLED env var must be true. Global emergency stop.
2Scope checkShop must have stock_sync_mode = 'edit' (seller opted in and consented).
3Identifier validationProduct must have the required identifiers for the marketplace (skuId+barcode for Uzum, offerId for Yandex).
4Quantity clampingNegative quantities clamped to 0. Prevents marketplace errors.
5Dry-run gateUnless confirm=true, returns what WOULD be sent without actually sending.
6Freshness guardChecks recentlyWrittenProductIds() — skips products written within 5 minutes to prevent sync-back reverting manual edits.
7URL-exact guardThe request URL must match the marketplace-readonly-guard.ts allowlist exactly. No URL manipulation possible.
8Retry with backoffOn transient failures, retries with exponential backoff. Logs every attempt.
Uzum Market Write
POST /v2/fbs/sku/stocks — sends skuId, barcode, amount, fbsLinked, dbsLinked. Method-exact + URL-exact allowlist in marketplace-readonly-guard.ts.
Yandex Market Write
PUT /v2/campaigns/{id}/offers/stocks — sends offerId + warehouseId + count + updatedAt. Same allowlist guard.
Full audit trail: Every write (success or failure) is logged in the stock_write_log table with the complete request body, response body, status code, and timestamp. The 5-minute freshness guard (recent-write-guard.ts) prevents the sync cron from reverting manual stock edits.
Read-Only Marketplace Guard
lib/marketplace-readonly-guard.ts — enforces the marketplace read-only rule at the HTTP layer. Every outbound marketplace request passes through this guard.
Default: Block All Writes
PUT, PATCH, DELETE are ALWAYS blocked. POST is blocked UNLESS the endpoint is in the POST-for-read whitelist (some marketplace APIs require POST for read operations — e.g., Yandex offer-mappings returns 405 on GET).
Exceptions (2 only)
1. Stock-write allowlist: method-exact + URL-exact entries for Uzum POST /v2/fbs/sku/stocks and Yandex PUT /v2/campaigns/*/offers/stocks. 2. Order-cancel allowlist: for the sanctioned oversell-cancel path.
Immutable rule: Any code that writes to a marketplace API outside these two exceptions (stock-write and order-cancel) is FORBIDDEN without explicit written approval from the repository owner. Violation = immediate revert.
